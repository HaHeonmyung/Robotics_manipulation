Ant 보행 실험 실행 안내서 — 처음 사용하는 사람용
작성 기준: 현재 설정한 Ubuntu 22.04 / RTX 4050 노트북

============================================================
0. 무엇부터 해보면 되나요?
============================================================
추천 순서:
  1) 아래 1번에서 터미널 준비
  2) 2번에서 이미 만든 영상 보기
  3) 3번에서 시뮬레이터 창으로 직접 보기
  4) 4번에서 100개 환경 점수 측정
  5) 5번에서 조건을 바꾸어 비교
  6) 7번에서 짧게 새로 학습

보행을 보기 위해 다시 학습할 필요는 없습니다.
이미 학습된 모델(final.pt)을 불러오면 됩니다.

용어:
  학습(train): 로봇이 경험을 쌓아 행동 방법을 새로 배우는 작업.
  평가(evaluate): 이미 배운 모델을 불러와 얼마나 잘 걷는지 측정.
  체크포인트(checkpoint): 학습된 신경망 등을 저장한 파일. 여기서는 final.pt.
  환경(environment): 로봇 한 대가 움직이는 시뮬레이션 공간.
  num_envs=100: 환경 100개를 동시에 실행한다는 뜻. 학습 100번이라는 뜻은 아님.
  에피소드(episode): 시작부터 넘어지거나 제한 시간에 도달할 때까지 한 번의 시도.
  seed: 난수 시작값. 비교할 때 조건을 맞추기 위해 사용.
  headless: 시뮬레이터 창을 띄우지 않고 계산만 하는 방식.
  baseline: 일정한 물성에서 학습한 기준 모델.
  randomized: 마찰·질량·교란을 바꾸어 가며 학습한 모델.

명령어는 우분투 터미널에 입력합니다. Python의 >>> 화면에 입력하지 마세요.
아래 설명 문장이나 구분선은 입력하지 말고, 명령어 줄만 복사하세요.
긴 명령어가 화면에서 두 줄로 보이더라도 실제로는 한 줄입니다.
한 작업이 끝나고 입력 커서가 돌아오면 다음 명령을 실행하세요.
처음에는 여러 시뮬레이터를 동시에 실행하지 마세요.

1. 터미널 열기와 실행 준비 — 새 터미널마다 필요
============================================================
Ctrl + Alt + T를 눌러 터미널을 엽니다.
현재 노트북에서는 아래 명령을 위에서부터 한 줄씩 실행하세요.

source /home/hhm/miniforge3/etc/profile.d/conda.sh
conda activate lerobot-arena
unset PYTHONPATH PYTHONHOME LD_PRELOAD
export PYTHONNOUSERSITE=1 OMNI_KIT_ACCEPT_EULA=YES
cd /home/hhm/Documents/Codex/2026-09-30/git-checkout-v2-3-0-error/outputs/ant-generalization

각 명령의 뜻:
  source ...conda.sh: 이 터미널에서 Conda 명령을 사용할 수 있게 준비.
  conda activate ...: 설치해 둔 시뮬레이션용 Python 환경 선택.
  unset ...: 다른 Python 설정과 충돌할 수 있는 환경변수 해제.
  export ...: 사용자 별도 패키지 간섭 방지 및 Isaac Sim 실행 설정.
  cd ...: 실험 코드와 모델이 있는 폴더로 이동.

잘 들어왔는지 확인:

pwd
which python
ls run.py runs/randomized_seed11/final.pt

기대 결과:
  pwd: 끝부분이 outputs/ant-generalization인 경로
  which python: /home/hhm/miniforge3/envs/lerobot-arena/bin/python
  ls: run.py와 final.pt가 오류 없이 표시됨

GPU 확인:

nvidia-smi

NVIDIA GPU 이름과 메모리 사용량 표가 나오면 드라이버가 응답하는 상태입니다.
터미널 앞에 (lerobot-arena)가 보이는지도 확인하세요.
이후 2~9번은 이 폴더, 이 터미널에서 실행한다고 가정합니다.
폴더를 이동했거나 터미널을 새로 열었다면 1번을 다시 실행하세요.
Python이나 시뮬레이터 명령 앞에는 sudo를 붙이지 마세요.

xdg-open videos/randomized-combined/rollout.mp4

같은 조건의 기준 모델 영상:

xdg-open videos/baseline-combined/rollout.mp4

명목 조건에서 무작위화 모델의 영상:

xdg-open videos/randomized-nominal/rollout.mp4

명목 조건에서 기준 모델의 영상:

xdg-open videos/baseline-nominal/rollout.mp4

이 명령은 동영상 재생기를 엽니다. 새 학습이나 평가를 하지 않습니다.
재생 앱이 열리지 않으면 아래 명령으로 폴더를 열고 rollout.mp4를 더블클릭하세요.

xdg-open videos

복합 조건의 기준 영상은 약 4.75초에 끝납니다.
해당 로봇의 첫 에피소드가 그때 종료됐기 때문이며 파일 손상이 아닙니다.
나머지 영상은 최대 10초만 녹화했습니다. 평가 자체는 최대 16초까지 진행했습니다.
영상에 주변 로봇이 함께 보일 수 있지만 카메라는 0번 환경의 로봇을 추적합니다.

3. 시뮬레이터 창에서 직접 실행해 보기
============================================================
우선 1번 준비를 마친 같은 터미널에서 실행하세요.
새 결과는 my_runs 안의 자동으로 만든 폴더에 저장합니다.
기존 제출용 runs, evaluation 폴더를 덮어쓰지 않습니다.

mkdir -p my_runs
VIEW_DIR=$(mktemp -d "$PWD/my_runs/view-XXXXXX")
python run.py evaluate --condition combined --num_envs 1 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --output "$VIEW_DIR"

--headless를 붙이지 않았으므로 시뮬레이터 창을 표시하는 실행입니다.
첫 창이 뜨기까지 기다리세요. 초기 셰이더 준비 때문에 시간이 걸릴 수 있습니다.
이 코드는 첫 에피소드가 끝나면 창을 닫고 자동 종료합니다.
시뮬레이션 시간은 최대 16초지만 실제 벽시계 시간과 같지는 않습니다.
창이 빨리 닫혀 보기 어렵다면 6번의 영상 녹화 방식을 사용하세요.

num_envs=1은 한 대를 관찰하기 위한 설정입니다.
제출 결과는 num_envs=100 기준이므로 이 한 대의 점수와 직접 비교하면 안 됩니다.
환경 개수 변경에 따라 난수 샘플도 달라질 수 있습니다.

기준 모델도 보고 싶다면 별도의 결과 폴더로 실행:

VIEW_DIR=$(mktemp -d "$PWD/my_runs/view-baseline-XXXXXX")
python run.py evaluate --condition combined --num_envs 1 --seed 20261007 --checkpoint runs/baseline_seed11/final.pt --output "$VIEW_DIR"

중간에 멈추려면 실행한 터미널을 클릭한 뒤 Ctrl + C를 누르세요.
중단한 평가는 metrics.json이 없거나 완성되지 않았을 수 있습니다.
보고서와 비교할 점수가 필요하면 중단하지 않고 자동 종료까지 기다리세요.

============================================================
4. 보고서처럼 100개 환경 평가하기
============================================================
아래 세 줄을 순서대로 실행하세요. 창을 띄우지 않으므로 GPU 부담이 더 적습니다.

mkdir -p my_runs
EVAL_DIR=$(mktemp -d "$PWD/my_runs/eval-XXXXXX")
python run.py evaluate --condition combined --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --output "$EVAL_DIR"

정상 완료하면 터미널에 EVALUATION_COMPLETE와 결과 숫자가 표시됩니다.
결과를 다시 확인:

cat "$EVAL_DIR/metrics.json"
echo "$EVAL_DIR"
xdg-open "$EVAL_DIR"

중요한 결과 항목:
  return_mean: 100개 첫 에피소드 누적 보상의 평균. 보행 속도만을 뜻하지 않음.
  return_std_population: 그 100개 에피소드 보상의 모집단 표준편차.
  survival_rate: 16초까지 낙상 없이 도달한 비율. 1.0이면 100%.
  forward_m_mean: x방향 속도를 적분해 구한 평균 전진량(m)의 근사값.
  episode_steps_mean: 첫 에피소드 평균 길이. 최대 960스텝.

episodes.csv에는 로봇별 결과가 100행 들어 있습니다.
표에서 survived_full_episode=True는 제한 시간까지 생존했다는 뜻입니다.
False이면 그 전에 종료됐거나 낙상 종료 조건을 충족한 경우입니다.

주의: 보고서의 요약표는 seed 11, 22, 33 모델 3개를 각각 평가한 평균입니다.
위 명령은 seed 11 모델 한 개만 평가하므로 요약표와 숫자가 같을 필요는 없습니다.
같은 모델·조건의 원본 결과는 아래 파일에서 확인할 수 있습니다.

cat evaluation/randomized_seed11/combined/metrics.json

GPU/드라이버와 실행 환경에 따라 재실행 수치가 완전히 동일하지 않을 수 있습니다.

============================================================
5. 다섯 가지 환경 조건을 하나씩 비교하기
============================================================
조건 이름과 뜻:
  nominal       : 명목 조건. 마찰 1, 질량 1배, 외부 교란 없음.
  slippery      : 미끄러운 조건. 마찰 0.2.
  heavy         : 무거운 조건. 질량 1.5배.
  strong_kicks  : 3초 간격 x/y 속도 각 축 최대 ±0.8 m/s 교란.
  combined      : 마찰 0.3, 질량 1.35배, 3초 간격 ±0.5 m/s 교란.

교란은 뉴턴(N) 단위의 힘이 아니라 속도에 더하는 오프셋입니다.
모든 조건은 평평한 바닥입니다. 조교의 비공개 환경을 재현한 것은 아닙니다.

먼저 이번 비교 결과를 담을 새 폴더를 만듭니다.

mkdir -p my_runs
COMPARE_DIR=$(mktemp -d "$PWD/my_runs/compare-XXXXXX")
echo "$COMPARE_DIR"

아래 명령을 하나씩 실행하고, 각 명령이 끝나면 다음 명령을 실행하세요.

python run.py evaluate --condition nominal --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --output "$COMPARE_DIR/nominal"

python run.py evaluate --condition slippery --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --output "$COMPARE_DIR/slippery"

python run.py evaluate --condition heavy --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --output "$COMPARE_DIR/heavy"

python run.py evaluate --condition strong_kicks --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --output "$COMPARE_DIR/strong_kicks"

python run.py evaluate --condition combined --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --output "$COMPARE_DIR/combined"

결과 폴더 열기:

xdg-open "$COMPARE_DIR"

기준 모델과 비교하려면 위 명령에서 체크포인트를
runs/baseline_seed11/final.pt로 바꾸고, 결과 폴더도 새로 만드세요.
같은 출력 폴더에 평가를 다시 실행하면 기존 평가 파일을 덮어쓸 수 있습니다.

다른 학습 시드의 모델은 다음처럼 지정합니다.
  runs/randomized_seed22/final.pt
  runs/randomized_seed33/final.pt
  runs/baseline_seed22/final.pt
  runs/baseline_seed33/final.pt

체크포인트 경로의 seed11은 "학습 때 사용한 시드"입니다.
명령의 --seed 20261007은 "평가 때 사용하는 시드"입니다.
서로 다른 역할이므로 학습 시드를 바꿔 비교할 때 평가 시드까지 바꾸지 마세요.

6. 내가 실행한 보행을 MP4로 녹화하기
============================================================

mkdir -p my_runs
VIDEO_DIR=$(mktemp -d "$PWD/my_runs/video-XXXXXX")
python run.py evaluate --condition combined --num_envs 100 --seed 20261007 --checkpoint runs/randomized_seed11/final.pt --headless --video --output "$VIDEO_DIR"
xdg-open "$VIDEO_DIR/rollout.mp4"

--video를 추가하면 0번 환경의 첫 에피소드를 최대 600프레임(10초) 저장합니다.
0번 환경이 일찍 종료되면 영상도 그때 끝납니다.
다른 환경들의 첫 에피소드 통계는 그 뒤에도 끝까지 계산합니다.
--headless와 --video를 같이 써도 화면 파일 생성은 가능합니다.
렌더링을 하므로 영상 없는 평가보다 메모리와 시간이 더 필요합니다.

최대 16초까지 녹화하려면 새 VIDEO_DIR을 만든 뒤
위 명령에 --video_frames 960을 추가하세요.

7. 새로 학습해 보기 — 먼저 짧은 연습부터
============================================================
학습하지 않고 2~6번만 해도 이미 만든 모델을 확인할 수 있습니다.
이 단계는 학습이 어떻게 진행되는지 궁금할 때 해보세요.

7-1. 가벼운 연습: 256개 환경, 20회 업데이트

mkdir -p my_runs
TRAIN_DIR=$(mktemp -d "$PWD/my_runs/train-practice-XXXXXX")
python run.py train --condition randomized --num_envs 256 --iterations 20 --seed 44 --headless --output "$TRAIN_DIR"

TRAINING_COMPLETE가 나오면 학습이 끝난 것입니다.
20회는 동작 확인용입니다. 잘 걷는 성능을 기대하기에는 매우 짧습니다.
터미널에 나오는 Learning iteration, Mean reward 등은 학습 중 기록입니다.
Mean reward가 높다고 미관측 환경에서도 반드시 잘 걷는 것은 아닙니다.

새로 학습한 모델 평가:

python run.py evaluate --condition combined --num_envs 100 --seed 20261007 --checkpoint "$TRAIN_DIR/final.pt" --headless --output "$TRAIN_DIR/eval-combined"

새 모델의 영상도 보고 싶다면:

python run.py evaluate --condition combined --num_envs 100 --seed 20261007 --checkpoint "$TRAIN_DIR/final.pt" --headless --video --output "$TRAIN_DIR/video-combined"
xdg-open "$TRAIN_DIR/video-combined/rollout.mp4"

7-2. 본 실험과 같은 학습량: 512개 환경, 500회 업데이트

TRAIN_DIR=$(mktemp -d "$PWD/my_runs/train-full-XXXXXX")
python run.py train --condition randomized --num_envs 512 --iterations 500 --seed 44 --headless --output "$TRAIN_DIR"

현재 노트북의 기존 실험에서는 1회 학습에 약 3~4분이 걸렸습니다.
초기 로딩, 전원 상태, 다른 프로그램에 따라 시간은 달라집니다.
노트북 전원을 연결하고 절전/잠자기 상태로 들어가지 않도록 해주세요.
기준 모델을 새로 학습하려면 새 폴더를 만든 뒤 --condition baseline을 사용하세요.
비교 실험에서는 환경 개수, 업데이트 횟수와 시드를 동일하게 맞추세요.

새 학습에는 train 모드의 --condition baseline 또는 randomized를 사용하세요.
처음부터 평가 조건까지 훈련에 포함하면 그 조건을 미관측 평가라고 부를 수 없습니다.

중단은 Ctrl + C입니다. 중단 시 final.pt가 없을 수 있습니다.
이 실행 스크립트는 중간 학습 재개 기능을 제공하지 않습니다.
완료된 final.pt가 있는 폴더를 다시 학습 대상으로 주면 덮어쓰기를 거부합니다.
새로 학습하려면 위처럼 새 폴더를 만드세요.

  http://127.0.0.1:6006

Scalars에서 Train/mean_reward 등의 항목을 확인합니다.
끝나면 TensorBoard를 실행한 터미널에서 Ctrl + C를 누르세요.
내가 새로 학습한 기록은 --logdir runs 대신 --logdir my_runs로 봅니다.
원격 접속 중이라면 브라우저도 학습 노트북 쪽에서 열어야 이 주소로 접속됩니다.

9. 전체 실험 재현에 관한 주의
============================================================
batch.py는 원래의 학습 6회와 평가 30회를 순서대로 실행하는 파일입니다.
현재 폴더에는 결과가 이미 있기 때문에 python batch.py만 실행하면
완료된 작업을 건너뜁니다. 새 학습을 하는 것이 아닙니다.

정말 처음부터 전체 실험을 다시 하려면 별도 폴더에 코드만 복사하세요.
아래 작업은 기존 제출 결과를 건드리지 않습니다.

REPRO_DIR=$(mktemp -d "$PWD/../ant-reproduction-XXXXXX")
cp run.py environment.py protocol.json batch.py analyze.py "$REPRO_DIR/"
python "$REPRO_DIR/batch.py"
python "$REPRO_DIR/analyze.py"
xdg-open "$REPRO_DIR"

6회 학습과 30회 평가가 진행되므로 개별 실행보다 오래 걸립니다.
첫 체험에는 이 단계 대신 3~7번을 추천합니다.
원본 폴더에서 analyze.py를 실행하면 원본 analysis 표와 그래프를 다시 씁니다.
my_runs 결과를 자동으로 요약해 주는 도구는 아닙니다.

10. 문제가 생겼을 때
============================================================
A. conda: command not found
  1번의 source ...conda.sh부터 다시 실행하세요.

B. ModuleNotFoundError: No module named 'isaaclab' 또는 'isaacsim'
  1번의 conda activate와 which python을 확인하세요.
  무작정 pip install이나 sudo pip install을 하지 마세요.
  이 노트북에서는 준비된 lerobot-arena 환경을 사용해야 합니다.

C. can't open file 'run.py' / No such file or directory
  현재 폴더가 다를 가능성이 큽니다. 1번의 cd와 ls를 다시 확인하세요.
  체크포인트 경로도 final.pt까지 정확히 입력했는지 확인하세요.

D. CUDA out of memory
  다른 Isaac Sim 실행을 종료하고 GPU를 사용하는 프로그램을 정리하세요.
  연습 학습은 --num_envs 512를 256 또는 128로 낮출 수 있습니다.
  num_envs를 바꾸면 학습량과 조건이 달라집니다.
  제출용 평가 수치와 비교할 때는 다시 --num_envs 100을 사용하세요.

E. GUI 창이 안 뜨거나 화면 관련 오류
  --headless를 사용한 명령은 원래 창이 뜨지 않습니다.
  우분투 데스크톱에 로그인한 터미널에서 GUI 명령을 실행하세요.
  그래도 어렵다면 6번처럼 --headless --video로 녹화해서 보세요.

F. [Warning] 메시지가 많이 나옴
  경고가 있다는 이유만으로 실패는 아닙니다.
  마지막의 TRAINING_COMPLETE / EVALUATION_COMPLETE와 결과 파일을 확인하세요.
  Traceback, CUDA 오류 등과 함께 종료되면 마지막 오류 내용을 보관하세요.

G. 결과 폴더 변수가 사라짐
  EVAL_DIR, TRAIN_DIR 등은 해당 터미널 안에서만 기억하는 변수입니다.
  터미널을 닫았으면 1번을 다시 실행하고 아래 명령으로 폴더를 찾으세요.

ls -lt my_runs
xdg-open my_runs

  이전 결과는 지워지지 않습니다. 각 폴더 안의 metrics.json 또는 final.pt를 찾으면 됩니다.

H. 같은 명령을 다시 해보고 싶음
  결과 폴더를 만드는 mktemp 줄부터 다시 실행하세요.
  같은 평가 폴더를 재사용하면 이전 결과를 덮어쓸 수 있습니다.

I. 오류를 파일에 저장해서 보여주고 싶음
  실행하려는 python 명령 끝에 다음 부분을 붙이면 터미널 출력도 파일에 남습니다.
  단, 이때 현재 터미널에서 같은 오류 로그 이름을 쓰면 이전 파일을 덮어씁니다.

  2>&1 | tee my_runs/error-log.txt

  python 명령 전체와 error-log.txt의 마지막 오류 부분을 함께 알려주세요.
  단순한 종료 직전 경고와 실제 원인을 구분하는 데 도움이 됩니다.

11. 다른 컴퓨터에서 이 안내서를 사용할 때
============================================================
이 TXT의 1번 명령은 현재 hhm 노트북의 설치 경로입니다.
다른 PC에서는 사용자명, Conda 위치, 환경 이름, 실험 폴더 위치가 다를 수 있습니다.
Ubuntu 22.04만 설치한 새 PC에서는 저장소를 받는 것만으로 실행되지 않습니다.
NVIDIA 드라이버, Python 환경, Isaac Sim 5.1, IsaacLab v2.3.0 및 의존성이 필요합니다.
기존에 만든 새 PC 설치 안내서를 먼저 적용한 뒤 사용하세요.
이 TXT는 설치 완료 후 실험을 실행하는 안내서입니다.

필요한 환경이 이미 준비된 PC에서 저장소 받기:

 git clone https://github.com/HaHeonmyung/Robotics_manipulation.git
 cd Robotics_manipulation/IsaacLab_RS/coursework/ant-generalization

그 PC의 시뮬레이션용 Conda 환경을 활성화한 뒤 2번 이후를 실행합니다.
이미 clone한 저장소가 있으면 새로 clone할 필요 없이 해당 폴더로 이동하세요.
GitHub의 ZIP이나 제출 ZIP을 풀었다면 압축을 푼 폴더 아래
IsaacLab_RS/coursework/ant-generalization으로 이동하면 됩니다.
코드를 내려받는 것과 Python 환경에 IsaacLab을 설치하는 것은 별개입니다.
